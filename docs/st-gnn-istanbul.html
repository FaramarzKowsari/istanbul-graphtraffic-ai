ST-GNN Istanbul: Spatiotemporal Graph Neural Networks for Traffic Forecasting

This page explains how an ST-GNN can be structured for Istanbul traffic forecasting in the İstanbul GraphTraffic AI research protocol. It covers sensor graphs, directed road topology, temporal windows, adaptive graph learning, Dynamic Graph Transformer modeling, multi-horizon forecasts, uncertainty and sensor-failure experiments. It does not claim final real-data superiority before confirmatory experiments are completed.

Why traffic forecasting is a spatiotemporal graph problem

Urban traffic is simultaneously spatial and temporal. A sensor records a time series, but its future state can depend on traffic arriving from connected corridors, upstream bottlenecks, bridge approaches and other locations. A graph representation keeps the identity of each traffic location while encoding relationships between locations, allowing a forecasting model to learn from both the network structure and the sequence of observations.

Graph construction for Istanbul traffic sensors

Geographic kNN graph

Nearby sensors are connected using geographic distance. This provides a transparent and reproducible baseline, but proximity alone does not guarantee a direct traffic-flow relationship.

Directed road-topology graph

Road connectivity and direction can define edges so that spatial message passing better follows the physical structure of the drivable network.

Learned adaptive graph

Node representations can learn predictive dependencies that are not fully expressed by static topology, enabling comparison between physical and data-driven connectivity.

ST-GNN and Dynamic Graph Transformer

The project compares simple temporal baselines with graph-based models. Persistence and Historical Average establish basic reference performance, while Temporal MLP and GRU models test how far temporal modeling can go without graph structure. An ST-GCN-style model provides a conventional spatiotemporal graph baseline. The Dynamic Graph Transformer is the principal research architecture for combining graph-aware spatial reasoning with temporal context and adaptive connectivity.

Multi-horizon Istanbul traffic forecasting

Forecasting is evaluated separately at +1h, +2h, +3h and +6h. Separating horizons is necessary because error behavior changes as the forecast moves farther from the most recent observations. The protocol therefore avoids collapsing all horizons into a single headline number.

Predictive uncertainty and sensor-failure resilience

Point accuracy is only one part of the problem. Quantile coverage and prediction interval width are used to examine predictive uncertainty. The pipeline also includes random and structured sensor-outage tests at 10%, 20% and 30%, measuring how forecasts degrade when parts of the observation graph become unavailable.

Research workflow

Evaluation includes MAE, RMSE, MAPE and R², together with uncertainty metrics, graph ablations, spatial and temporal slices, failure-resilience tests and statistical comparisons where appropriate.

Evidence status: v0.1.0 is a research protocol and executable pipeline. Synthetic data verify execution; they are not presented as real Istanbul benchmark evidence.
